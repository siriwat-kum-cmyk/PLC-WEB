บทที่ 1: แนวคิดและวัตถุประสงค์โครงการ

โครงการ Alarm & Maintenance Management System เป็นเว็บแอปพลิเคชันที่ได้รับการพัฒนาขึ้นตามข้อกำหนดของรายวิชา Programming in Automation Systems เพื่อจำลองและสนับสนุนการบริหารจัดการระบบอัตโนมัติในโรงงานอุตสาหกรรม โดยมีหัวใจสำคัญคือการนำเทคโนโลยีเว็บสมัยใหม่มาผสานเข้ากับขีดความสามารถของ AI ในทุกขั้นตอนของการพัฒนา

1.1 วัตถุประสงค์หลักของระบบ

  • ตรวจสอบสถานะเครื่องจักร (Machine Monitoring): ทราบภาพรวมจำนวนเครื่องจักรที่กำลังทำงาน (Running), หยุดทำงาน (Stop), เกิดแจ้งเตือน (Alarm) หรืออยู่ระหว่างการซ่อมบำรุง (Maintenance) แบบเรียลไทม์
  • จัดการสัญญาณเตือน (Alarm Incident Workflow): บันทึกรหัสการแจ้งเตือน (Alarm Code), รายละเอียด, เวลาที่เกิดเหตุ, วิเคราะห์สาเหตุ และติดตามสถานะตั้งแต่เปิดแจ้งเหตุจนกระทั่งปิดงานเสร็จสิ้น
  • วางแผนและบันทึกประวัติการซ่อมบำรุง (Maintenance Tracking): ออกใบสั่งซ่อมบำรุงเชิงป้องกัน (PM) และแก้ไข (BM/CM) พร้อมทั้งรองรับสถานะการรออะไหล่ (Waiting Part) ตามข้อกำหนด Change Request
  • ควบคุมสิทธิ์ความปลอดภัย (Role-Based Access Control): แยกสิทธิ์การเข้าถึงระหว่างผู้ดูแลระบบ (Admin), ช่างเทคนิค (Technician) และผู้สังเกตการณ์ (Viewer)

1.2 ตารางเปรียบเทียบความครบถ้วนตามโจทย์ข้อกำหนด (3.1 - 3.12)

ข้อกำหนด สิ่งที่โจทย์กำหนด ผลการพัฒนาในระบบ
3.1 Auth & Role Login/Logout ด้วย Supabase, มี Role Admin และ Technician พร้อมควบคุมสิทธิ์ ครบถ้วน รองรับ Login/Logout, มี Admin, Technician และเพิ่ม Viewer (Bonus)
3.2 Machine Master บันทึก ID, Name, Type, Location, Status (Running, Stop, Alarm, Maintenance) เพิ่ม/แก้/ลบได้ ครบถ้วน มี CRUD แบบสมบูรณ์ ตรวจจับรหัสซ้ำอัตโนมัติ
3.3 Alarm Record บันทึก Machine, Code, Desc, Time, Cause, Status (Open, In Progress, Closed) ครบถ้วน มี Workflow ปรับสถานะ 1-Click และบันทึกวิธีแก้ไข (Resolution)
3.4 Maintenance บันทึก Machine, Type, Problem, Action Taken, Technician, Date, Status ครบถ้วน รองรับสถานะ Waiting Part ตามโจทย์ Change Request
3.5 Search & Filter ค้นหาหรือกรองข้อมูลได้อย่างน้อย 2 เงื่อนไข ระบบ Multi-Filter ค้นหาคำสำคัญ + กรองสถานะ + กรองประเภท/ช่างได้พร้อมกัน
3.6 Dashboard แสดงจำนวนเครื่องจักรทั้งหมด, สรุปสถานะ, ยอด Alarm, งานซ่อม และกราฟ SCADA KPI Cards + กราฟ Donut สัดส่วนสถานะ + กราฟแท่งวิเคราะห์ความรุนแรง
3.7 Validation ห้ามเว้นว่าง, Machine ID ห้ามซ้ำ, ป้องกันค่าไม่เหมาะสม และแจ้งเตือนข้อผิดพลาด ระบบ Modal Form Validation พร้อมข้อความแจ้งเตือนสีแดง และตรวจ Unique ID
3.8 Database Supabase: ตาราง profiles, machines, alarms, maintenance พร้อม Foreign Keys Schema SQL สมบูรณ์ มีครบทุกตาราง + Foreign Key + RLS Policies + Triggers
3.9 GitHub เก็บบน GitHub, มีประวัติ Commit ระหว่างการพัฒนา ไม่โยนโค้ดครั้งเดียว จัดเก็บเรียบร้อย มี 11 Commits ประวัติการพัฒนาชัดเจน
3.10 CI Actions GitHub Actions อย่างน้อย 1 Workflow ตรวจสอบ Install, Build หรือ Test ไฟล์ ci.yml ตรวจสอบทั้ง Lint, TypeScript Type-check และ Next.js Build
3.11 Vercel Deploy ด้วย Vercel เปิดใช้งานได้จริง คอนฟิก Vercel พร้อม Dual-mode Demo Architecture เปิดใช้ได้ทันที
3.12 README ชื่อโครงการ, ฟังก์ชัน, Tech Stack, Database, วิธีติดตั้ง, URL, รายงาน AI เอกสาร README.md สมบูรณ์ ครอบคลุมทุกหัวข้อตามเกณฑ์ 100%

บทที่ 2: สถาปัตยกรรมและเทคโนโลยีที่ใช้

ระบบถูกออกแบบบนสถาปัตยกรรม Modern Web Full-Stack โดยแยกส่วนอย่างเป็นระบบระหว่าง Presentation Layer, Business Logic Layer และ Cloud Persistence Layer

สถาปัตยกรรม Dual-Mode Data Architecture (จุดเด่นของระบบ)
ระบบรองรับการทำงาน 2 โหมดพร้อมกัน:
  1. Live Supabase Mode: เมื่อเชื่อมต่อกับฐานข้อมูล Cloud ผ่าน Environment Variables ข้อมูลจะถูกซิงก์แบบ Real-time เข้าสู่ PostgreSQL Database
  2. Offline Demo Fallback Mode: หากยังไม่ได้ตั้งค่า API Key หรือขณะทดสอบระบบ ตัวแอปพลิเคชันจะจำลองฐานข้อมูลตัวอย่างใน Local Storage ทำให้กรรมการหรือผู้ตรวจงานสามารถเปิดลิงก์ Vercel แล้วทดลองกดใช้งานได้ทันที 100% โดยที่ระบบไม่ Error หรือพัง

2.1 ตารางสรุปชุดเทคโนโลยี (Tech Stack)

องค์ประกอบ เทคโนโลยีที่เลือกใช้ หน้าที่และความสำคัญในระบบ
Frontend Framework Next.js 14+ (App Router) โครงสร้างหลักแบบ React Server & Client Components, Dynamic Routing และ Static Site Generation
UI Styling Tailwind CSS ออกแบบสไตล์ SCADA Industrial Theme รองรับ Responsive และ Dark / Light Mode
Icons & Charts Lucide React & Recharts ไอคอนสไตล์วิศวกรรมอุตสาหกรรม และการแสดงผลกราฟสถิติแบบ Interactive
Database & Auth Supabase (PostgreSQL) ฐานข้อมูลเชิงสัมพันธ์บน Cloud, ระบบยืนยันตัวตน (Authentication) และการรักษาความปลอดภัย RLS
Version Control Git & GitHub จัดการ Source Code และประวัติการพัฒนา 11 Commits อย่างมีระเบียบ
CI/CD Pipeline GitHub Actions ตรวจสอบคุณภาพโค้ดอัตโนมัติ (Automated Linting, Type Checking, Production Build)
Cloud Deployment Vercel Platform Deploy เว็บแอปพลิเคชันบนโครงข่าย Edge Network ทั่วโลก พร้อมระบบ Auto-Deploy เมื่อ Git Push

บทที่ 3: โครงสร้างฐานข้อมูลและระบบความปลอดภัย

ฐานข้อมูลได้รับการออกแบบบนหลักการ Database Normalization โดยจัดเก็บใน Supabase PostgreSQL แบ่งออกเป็น 5 ตารางหลัก:

ชื่อตาราง ฟิลด์สำคัญ (Attributes) คำอธิบายและความสัมพันธ์ (Relationships)
profiles id, email, full_name, role, department, created_at จัดเก็บข้อมูลผู้ใช้และระดับสิทธิ์ (Admin, Technician, Viewer) อ้างอิงกับ auth.users.id
machines id, machine_id (UNIQUE), name, type, location, status, description ทะเบียนเครื่องจักรหลัก สถานะ: Running, Stop, Alarm, Maintenance
alarms id, machine_id, alarm_code, description, severity, triggered_at, cause, status, resolution บันทึกเหตุการณ์แจ้งเตือน ผูกกับ machines(id) ON DELETE CASCADE
maintenance_records id, machine_id, maintenance_type, problem, action_taken, technician_name, scheduled_date, status บันทึกใบสั่งซ่อมบำรุง ผูกกับ machines(id) รองรับสถานะ Waiting Part
audit_logs id, user_id, action, entity_type, entity_id, details, ip_address, created_at บันทึกประวัติการกระทำในระบบเพื่อความโปร่งใสและตรวจสอบย้อนหลัง (Audit Trail)
ระบบความปลอดภัย Row Level Security (RLS)
ระบบมีการเปิดใช้งาน RLS ทุกตาราง เพื่อบังคับใช้สิทธิ์ในระดับ SQL:
  • Admin: ได้รับสิทธิ์ Full Access (SELECT, INSERT, UPDATE, DELETE) ทุกตาราง
  • Technician: ได้รับสิทธิ์ SELECT ทุกตาราง และ UPDATE/INSERT เฉพาะตาราง alarms และ maintenance_records
  • Viewer: ได้รับสิทธิ์เฉพาะ SELECT (Read-only) เท่านั้น ไม่สามารถแก้ไขหรือลบข้อมูลได้

บทที่ 5: คู่มือการใช้งานระบบทีละฟังก์ชัน

5.1 SCADA KPI Dashboard & Analytics

หน้าแรกของระบบทำหน้าที่เป็นศูนย์ควบคุมภาพรวม (Command Center) สำหรับผู้บริหารและวิศวกรโรงงาน:

  • การ์ดตัวเลขสรุปสถานะ (KPI Metric Cards):
    • Total Machines: จำนวนเครื่องจักรทั้งหมดในสายการผลิต
    • Running: จำนวนเครื่องจักรที่กำลังเดินสายการผลิตปกติ (กรอบสีเขียว)
    • Stop: จำนวนเครื่องจักรที่หยุดพักหรือหยุดรอคำสั่ง (กรอบสีเทา)
    • Alarm: จำนวนเครื่องจักรที่ติดสัญญาณเตือนขัดข้อง (กรอบสีแดงพร้อมกระพริบเตือน)
    • Maintenance: จำนวนเครื่องจักรที่อยู่ระหว่างแผนซ่อมบำรุง (กรอบสีส้ม)
  • กราฟวิเคราะห์แบบตอบสนอง (Interactive Recharts):
    • Status Distribution Chart: กราฟวงแหวน (Donut Chart) แสดงสัดส่วนเปอร์เซ็นต์สถานะเครื่องจักร
    • Alarm Severity Chart: กราฟแท่งแสดงจำนวนการแจ้งเตือนตามระดับความรุนแรง (Critical, Major, Minor, Warning)
    • Maintenance Type Chart: กราฟแท่งแจกแจงประเภทงานซ่อม (Preventive, Corrective, Breakdown)

5.2 Machine Master Management (ทะเบียนเครื่องจักร)

โมดูลสำหรับจัดการข้อมูลเครื่องจักรหลักในสายการผลิต (CRUD: Create, Read, Update, Delete):

1
การเพิ่มเครื่องจักรใหม่ (Add Machine) กดปุ่ม + เพิ่มเครื่องจักร ที่มุมบนขวา กรอกข้อมูลใน Modal: Machine ID (เช่น CNC-001), ชื่อเครื่องจักร, ประเภท (เช่น CNC Milling, Robot Arm), สถานที่ติดตั้ง (Location) และสถานะเริ่มต้น จากนั้นกดบันทึก
2
การค้นหาและกรองหลายเงื่อนไข (Multi-Filter) สามารถพิมพ์ค้นหาด้วยรหัสหรือชื่อเครื่องจักรในช่องค้นหา พร้อมทั้งเลือก Dropdown กรองสถานะ (Running, Stop, Alarm, Maintenance) และกรองตามประเภทเครื่องจักรได้พร้อมกันทันที
3
การแก้ไขและลบข้อมูล (Edit / Delete) สามารถกดไอคอนดินสอเพื่อแก้ไขสเปกเครื่อง หรือกดไอคอนถังขยะสีแดงเพื่อลบเครื่องจักร (เฉพาะ Role Admin เท่านั้น) ระบบจะมีหน้าต่างยืนยันเพื่อป้องกันการลบโดยไม่ตั้งใจ

5.3 Alarm Incident Management (การจัดการสัญญาณเตือน)

โมดูลติดตามเหตุการณ์ขัดข้องของเครื่องจักร เพื่อลดระยะเวลาการหยุดชะงัก (Downtime):

  • วงจรสถานะของสัญญาณเตือน (Alarm Lifecycle):
    1. Open : สัญญาณเตือนถูกกระตุ้นขึ้น ยังไม่มีช่างเข้าไปตรวจสอบ
    2. In Progress : ช่างเทคนิคกดรับงานและกำลังตรวจสอบสาเหตุหน้างาน
    3. Closed : ได้รับการแก้ไขเรียบร้อย บันทึกสาเหตุและแนวทางแก้ไขแล้ว
  • ปุ่มเลื่อนสถานะในคลิกเดียว (1-Click Quick Action): ที่แต่ละรายการแจ้งเตือน จะมีปุ่มสำหรับกดรับเรื่อง (Acknowledge) หรือปิดงาน (Resolve) ได้ทันทีโดยไม่ต้องเปิดฟอร์มหลายขั้นตอน

5.4 Maintenance Records & Waiting Part (งานซ่อมบำรุง)

โมดูลบริหารจัดการใบสั่งซ่อมบำรุง ทั้งแบบตามรอบเวลา (Preventive) และแบบแก้ไขเหตุฉุกเฉิน (Breakdown):

  • ข้อมูลในใบสั่งซ่อม: รหัสเครื่องจักร, ปัญหาที่พบ (Problem Description), แผนการดำเนินงาน (Action Taken), ชื่อช่างผู้รับผิดชอบ, วันที่นัดหมาย และสถานะ
  • สถานะ Waiting Part (Change Request ตามโจทย์): ในกรณีที่ช่างเข้าตรวจสอบแล้วพบว่าชิ้นส่วนหรืออะไหล่ขาดสต็อก ช่างสามารถเลือกเปลี่ยนสถานะเป็น Waiting Part เพื่อระงับเวลางานชั่วคราวและแจ้งฝ่ายจัดซื้อได้ทันที

5.5 Machine History Timeline (ลำดับประวัติเหตุการณ์เครื่องจักร)

ฟังก์ชันโบนัสพิเศษที่ช่วยให้วิศวกรสามารถคลิกที่รหัสเครื่องจักรใดๆ เพื่อเปิดดูหน้า History Timeline (เช่น /machines/CNC-001) ระบบจะรวบรวมเหตุการณ์ทั้ง Alarms ที่เคยเกิดขึ้น และประวัติงานซ่อม Maintenance ทั้งหมดของเครื่องนั้นมาเรียงลำดับตามวันเวลา (Chronological Feed) เสมือนสมุดประวัติประจำตัวเครื่องจักร

บทที่ 7: กฎการตรวจสอบความถูกต้องของข้อมูล (Input Validation)

ระบบติดตั้งกลไกป้องกันความผิดพลาดของผู้ใช้งาน (Poka-Yoke) เพื่อรักษาความถูกต้องของข้อมูล (Data Integrity):

กฎข้อห้ามสำคัญ 4 ประการ (System Validation Rules)
  1. ห้ามเว้นว่างช่องข้อมูลสำคัญ (Mandatory Fields): ช่องที่มีเครื่องหมายดอกจันสีแดง เช่น Machine ID, ชื่อเครื่องจักร, สาเหตุ Alarm, ช่างผู้รับผิดชอบ จะไม่สามารถกดบันทึกได้หากเว้นว่าง
  2. Machine ID ห้ามซ้ำเด็ดขาด (Duplicate Prevention): หากผู้ใช้พิมพ์ Machine ID ที่มีอยู่ในระบบแล้ว (เช่น กรอกซ้ำว่า CNC-001) ระบบจะขึ้นแถบเตือนสีแดงทันที และปุ่มบันทึกจะถูกปิดการทำงาน
  3. รูปแบบข้อมูลต้องถูกต้อง (Format & Type Safety): มีการบังคับเลือกตัวเลือกผ่าน Dropdown ป้องกันการพิมพ์ค่าที่ไม่อยู่ในมาตรฐาน
  4. การแจ้งเตือน Error ชัดเจน: แสดงแถบแบนเนอร์สีแดงพร้อมข้อความระบุชัดเจนว่าต้องแก้ไขจุดใด
