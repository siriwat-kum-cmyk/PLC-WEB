1. โครงสร้างฐานข้อมูล
👤 ผู้บรรยายคนที่ 1

โครงสร้างฐานข้อมูลและการรักษาความปลอดภัย (Database & Security)

การออกแบบฐานข้อมูลตามหลัก Normalization พร้อมความสัมพันธ์ Foreign Keys และ RLS
🗃️ 5 ตารางหลักใน Supabase (PostgreSQL)
• profiles : เก็บสิทธิ์ผู้ใช้ (Admin, Technician, Viewer)
• machines : ทะเบียนเครื่องจักร (Machine ID UNIQUE)
• alarms : ประวัติการแจ้งเตือน (Foreign Key ➔ machines)
• maintenance_records : ใบสั่งซ่อม (รองรับ Waiting Part)
• audit_logs : บันทึกประวัติการกระทำเพื่อความโปร่งใส
🛡️ Row Level Security (RLS Policies)
• Admin: สิทธิ์เต็มทุกตาราง (SELECT, INSERT, UPDATE, DELETE)
• Technician: แก้ไขงานซ่อมและรับแจ้งเหตุ Alarm ได้
• Viewer: เรียกดูข้อมูลได้อย่างเดียว (Read-only)
• บังคับใช้ความปลอดภัยถึงระดับ Database Engine โดยตรง
Foreign Key: alarms.machine_id ➔ machines.id (ON DELETE CASCADE)
Foreign Key: maintenance_records.machine_id ➔ machines.id (ON DELETE CASCADE)

Machine Master Management & Data Validation

การจัดการข้อมูลเครื่องจักรแบบสมบูรณ์ พร้อมระบบป้องกันรหัสเครื่องจักรซ้ำ
📋 คุณสมบัติของ Machine Master
• บันทึกข้อมูลครบถ้วน: Machine ID, Name, Type, Location, Status, Description
• สถานะมาตรฐาน 4 สถานะ:
  Running เดินเครื่องปกติ
  Stop หยุดการทำงาน
  Alarm เครื่องจักรแจ้งเตือนขัดข้อง
  Maintenance กำลังซ่อมบำรุง
• CRUD ครบวงจร: สร้างใหม่, แก้ไข, ลบข้อมูล และดูรายละเอียด
🛡️ ระบบ Input Validation & Duplicate Protection
• Machine ID ห้ามซ้ำเด็ดขาด: ตรวจสอบแบบ Real-time ทันทีที่พิมพ์ หากซ้ำจะแจ้งเตือนแถบสีแดงและล็อคปุ่มบันทึก
• ห้ามเว้นว่างช่องสำคัญ: มีการบังคับกรอกข้อมูลที่จำเป็นทุกฟิลด์
• Multi-Filter ค้นหาฉับไว: ค้นหาด้วยคำสำคัญ + กรองสถานะ + กรองประเภทเครื่องจักรได้พร้อมกัน

Alarm Incident Management & Lifecycle Workflow

กระบวนการติดตามสัญญาณเตือนขัดข้องตั้งแต่เกิดเหตุจนแก้ไขแล้วเสร็จ (3 ขั้นตอน)
1. Open (เกิดเหตุ)
• สัญญาณเตือนถูกกระตุ้นขึ้นในสายการผลิต
• บันทึก Alarm Code, วันที่/เวลา, สาเหตุเบื้องต้น
• แจ้งเตือนสัญลักษณ์กระพริบแดงใน Dashboard
• รอดำเนินการรับเรื่อง
2. In Progress (รับเรื่อง)
• ช่างเทคนิคกดรับงาน (Acknowledge)
• เข้าตรวจสอบหน้างานและตรวจเช็กระบบไฟฟ้า/กลไก
• เครื่องจักรเข้าสู่โหมดการแก้ไขปัญหา
• บันทึกความคืบหน้าระหว่างปฏิบัติงาน
3. Closed (ปิดงาน)
• แก้ไขข้อขัดข้องเรียบร้อยแล้ว
• บันทึกวิธีแก้ไข (Resolution) เพื่อเป็นฐานความรู้
• รีเซ็ตสถานะเครื่องจักรกลับสู่ความพร้อมใช้งาน
• บันทึกเวลาที่ใช้ในการกู้คืนระบบ
⚡ 1-Click Quick Action Button
ช่างเทคนิคสามารถกดปุ่มเลื่อนสถานะจาก Open ➔ In Progress ➔ Closed ได้จากตารางรายการทันที เพื่อความรวดเร็วในการปฏิบัติงานจริง

👤 ผู้บรรยายคนที่ 2

Maintenance Record & การรองรับสถานะ "Waiting Part"

การออกใบสั่งซ่อมบำรุงเชิงป้องกันและแก้ไข พร้อมตอบโจทย์ Change Request ข้อกำหนดพิเศษ
🔧 การบริหารงานซ่อมบำรุง (Maintenance)
• ประเภทงานซ่อม: Preventive (PM), Corrective (CM), Breakdown (BM)
• ข้อมูลครบถ้วน: ระบุเครื่องจักร, อาการปัญหา (Problem), แผนการดำเนินงาน (Action Taken), ช่างผู้รับผิดชอบ และวันนัดหมาย
• สถานะมาตรฐาน: Scheduled ➔ In Progress ➔ Completed
⭐ สถานะ "Waiting Part" (Change Request)
• ความสำคัญ: รองรับกรณีเข้าซ่อมแล้วพบว่าอะไหล่ขาดสต็อก หรือต้องรอการสั่งซื้อจากต่างประเทศ
• การทำงาน: สามารถเลือกสถานะ Waiting Part ได้ทันที
• ช่วยแยกแยะงานซ่อมที่ล่าช้าเพราะรออะไหล่ ออกจากงานซ่อมทั่วไปได้อย่างแม่นยำ

🐙 GitHub Actions Continuous Integration (CI)
• ทุกครั้งที่มีการ git push ไปยังสาขา main ระบบจะรันอัตโนมัติ:
  1. ติดตั้ง Dependencies (npm ci)
  2. ตรวจสอบโค้ดสะอาด (npm run lint ➔ 0 errors)
  3. ตรวจสอบความถูกต้องของ Type (npm run type-check ➔ 0 errors)
  4. ตรวจสอบการ Build สำหรับ Production (npm run build)
